# Table 表格

Source: MasterGo document `行知app-规范`, nodes `XingZhi App - Design System-Table 表格`、`Table 表格-交互说明`、`Table 表格-页面范例`、`Table 表格-组件`（`6:97856`、`6:98851`、`6:000374`、`6:97817`）。

## 定位与基础结构

- Table 用于展示大量结构化数据，并支持查看、排序、筛选、搜索或复杂操作。
- 基础结构为顶部横向表头 + 多行数据；同一列保持稳定的列宽、对齐方向和内容语义。
- 手机端支持竖屏和横屏。列数或内容宽度超过视口时使用横向滚动，不压缩到不可读。
- 信息单元格允许 `1–3` 行：主文本 `1–2` 行、副文本最多 `1` 行，主副文本合计不得超过 `3` 行。

## 页面级与卡片级

- 页面级表格以 `375px` 移动画布为基础，可开启或关闭固定列。
- 关闭固定列时，表格内容宽度可超过视口；画板中的 `416px` 是横向滚动示例，不是固定全局宽度。
- 卡片级表格宽 `343px`、圆角 `8px`，可组合顶部账户/条件选择区和表格内容。
- 卡片级示例顶部选择区高约 `48px`，使用 `#F5F7FA` 背景；其下表格按内容高度延展。示例总高 `244px` 不是固定模板高度。
- 页面级和卡片级使用同一单元格规则；容器层级只改变外部宽度、圆角和顶部组合区。

## 表头单元格

- 基础表头高 `34px`，上下内边距 `10px`、左右内边距 `12px`，底部分隔线 `0.5px #E6EBF0`。
- 表头文字通常为 `12px/17px`、`#999999`；左侧文本列左对齐，数值与指标列右对齐。
- 表头右侧最多附加一个列级操作，如排序或筛选；图标参考 `12 × 12px`，与文字间距 `4px`。
- 标题单元格支持四个独立维度：标题单行/多行、带/不带副标题、前图标 on/off、后图标 on/off。
- 单行且无副标题的标题单元格高约 `40px`；多行无副标题约 `60px`；单行带副标题约 `62px`；多行带副标题约 `82px`。
- 前图标用于状态、类型或核心标识；后图标用于清除、进入、操作等明确行为。无业务语义时不要仅为装饰开启。

## 内容单元格

- 单行内容单元格高约 `40px`，内边距通常为 `12px`。
- 双行/带副标题内容单元格高约 `62px`；标题多行或主副文本达到三行时高约 `82px`。
- 主文本通常为 `14px/20px`、`#222222`；副文本为 `12px/18px`、`#999999`，主副文本间距 `4px`。
- 文本列左对齐；数字、金额、比例和日期等指标列右对齐。数字可按产品既有规则使用数字字体，不改变颜色语义。
- 内容单元格支持前置/后置 `16 × 16px` 图标；图标与文字间距通常 `4–8px`。
- 长单行内容使用省略；允许多行的标题按 `2` 行上限截断，不能无限增高破坏同行对齐。

## 输入型内容单元格

- 表格允许输入型内容单元格，用于行内编辑；示例外层高 `62px`、上下内边距 `12px`。
- 输入区使用 `#F5F7FA` 背景，示例内边距 `6px 8px`、圆角 `2px`；输入文字 `14px/20px`。
- 未输入显示预提示；编辑状态、校验、禁用和提交行为遵循 `input.md` 与 `form.md`。
- 行内编辑不能挤压相邻列或改变整行对齐；错误提示需要额外空间时按整行统一增高。

## 列与对齐

- 列宽由信息优先级和内容长度决定。画板中的 `142/84/76px` 等是示例列宽，不是固定 token。
- 标题/核心信息列通常较宽并左对齐；普通数值列右对齐；操作列保持最小可用宽度。
- 行/列边界使用 `#E6EBF0` 的 `0.5px` 底部分隔线，避免厚重全网格。
- 同一数据行的各列必须使用一致的行高档位：`40px`、`62px` 或 `82px`，不能各列独立改变高度。

## 固定列与横向滚动

- 横向内容较多时，将核心信息列固定在左侧，滚动列在其下方横向移动。
- 若单行存在核心操作，将唯一核心操作列固定在右侧；不允许固定多个核心操作。
- 特殊场景下，自选添加/清除可放在核心信息标题文本右侧，但不能与右侧核心操作重复。
- 固定列与滚动区之间使用轻微阴影提示层级；固定列必须覆盖滚动内容，边界不能出现文字穿透。
- 横向滚动保持表头与内容列同步，首尾列到达边界时正确收起相应阴影。

## 操作表格

- 排序：针对单一列指标升序或降序；排序入口紧邻该列表头，不得控制无关列。
- 筛选：用于批量结构化筛选，默认关闭；开启后使用 Tabs 或 `filter-view.md` 承载条件。
- 编辑/设置：表格顶部右侧提供批量操作或个性化编辑入口。
- 单个表头右侧最多出现一个操作项；多个操作应收纳到表格级编辑/设置入口。
- 行级核心操作通常用于整条数据的删除、清除或编辑；只保留一个高频核心操作，其余进入更多操作。

## 卡片级顶部组合

- 卡片级表格可在表格上方放置账户、组合或条件选择区；标题使用卡片层级标题，右侧使用下拉箭头。
- 顶部选择区与表格滚动区职责分离：切换条件刷新整张表格，不随横向列一起滚动。
- 账户名、代码和业务示例仅用于展示组合方式，不得作为真实页面固定文案。

## 交互与状态

- 排序需明确默认、升序、降序三种状态；再次操作按产品规则切换或恢复默认。
- 筛选开启后应显示已生效状态，并提供清除或恢复默认路径。
- 横竖屏切换、横向滚动和返回页面时，按业务需要保留排序、筛选与滚动位置。
- 空数据、加载、失败和无权限分别遵循 `empty-state.md`、`loading.md` 和对应反馈规范；不要用空白表格表达异常。
- 可点击行、可编辑单元格和纯展示内容必须具有清楚的视觉与交互区别。

## 来源边界

- 页面范例中的产品名、证券代码、账户、净值、涨跌幅和数量仅是示例数据，不是产品默认内容。
- 规范画板中的 `375 × 280px`、`343 × 244px` 等是组件组合示例；高度应由真实行数和单元格档位计算。
- `40/62/82px` 是内容行语义档位；表头基础高度为 `34px`，不要混为同一尺寸体系。

## 检查清单

- 检查页面级/卡片级、固定列 on/off 和横竖屏场景是否选择正确。
- 检查表头 `34px`、内容行 `40/62/82px`、主副文本总行数不超过 `3`。
- 检查标题单行/多行、副标题、前后图标变体是否按语义启用。
- 检查文本左对齐、数字右对齐、列宽、截断和同行统一高度。
- 检查输入型单元格的背景、内边距、校验和行高联动。
- 检查核心信息左固定、唯一核心操作右固定、滚动同步与边界阴影。
- 检查排序、筛选、编辑/设置入口的数量、位置、状态和作用范围。
- 检查字体、颜色、分隔线、空态、加载和无权限状态是否调用对应行知规范。
